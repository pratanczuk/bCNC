# Visual conformity audit — Foil Studio

**Verdict: the current implementation does not follow the original visual design 1:1.** The shared palette and parts of the workflow are present, but the window architecture, control recipes, sizing and several compact layouts differ materially. The earlier implementation should be described as a partial adaptation, not completion of the proposal.

Reviewed local commit **5dfcf38**, 15 September 2026. This audit changes documentation only.

## Evidence and interpretation

- Compared the [written design proposal](../foil-studio-ui-proposal.md) and the original companion HTML/CSS/JavaScript source with freshly rendered application windows.
- Inventoried all **19 application window families**: the main workspace, 13 design/project/guide dialogs, Library, Settings, Connection, Machine and the shared error dialog. Reviewed their settings pages, editor tabs and representative states separately below.
- Captured desktop **1280×900** and compact **390×844** application sizes under Xvfb. Secondary windows use their actual application-selected dimensions, which are recorded in [measurements.json](measurements.json). Window-manager decorations are excluded.
- Temporary test preferences, sample leaf SVG, empty/populated libraries and simulated job/controller states were used. No machine commands or real device transitions were exercised. The initial disconnected Running/Paused fixtures are retained for transparency; use the connected simulated captures for the representative state comparison.
- The proposal has visual concepts for principal destinations and selected editors, plus written requirements for the rest. It is not a complete pixel-level reference set. Therefore no invented similarity percentage or pixel-diff pass rate is given. “Partial” means some structure matches, not visual acceptance.
- The local HTML reference could not be opened by the browser’s URL policy; this audit compares its source-defined layout/tokens rather than claiming a newly rendered browser comparison.
- Native Import and unsaved-confirmation dialogs were also captured. Other platform prompts (save/export, font/color picking, rename and deletion confirmations) were inventoried through their call sites; their individual content variants were not all rendered. The compact unsaved-confirmation capture is unavailable. The audit does not claim every native dialog permutation was visually tested.
- Later user decisions—Properties replacing Selection, additive import, and Automatic mat-loading default—are intentional overrides and are not counted as design defects.

**Evidence set: 109 captures across 55 named pages/states.**

## Highest-priority findings

1. **Compact controls are clipped.** [Size & arrange](ArrangeDialog-compact.png) loses the Resize/Rotate/Place captions; [Planning defaults](settings-planning-defaults-compact.png) clips headings and collides labels/values; [Support](settings-language-and-support-compact.png) clips Copy; [Settings → Machine](settings-machine-control-compact.png) clips action rows. These prevent acceptance before any fine visual matching.
2. **The specified screen architecture is not implemented.** Desktop tools remain floating windows; compact tools are resized floating windows, not focused pages. Prepare and Cut retain a scrolling sidebar and editor toolbar. Expanded Design lacks the proposed tool rail/docked-layer arrangement.
3. **The control system is incomplete.** Shape/Combine choices are still rectangular radio controls. Entries, comboboxes, checkboxes, notebooks, menus and trees retain mixed native styling. Rounded action buttons alone do not establish conformity.
4. **Touch and job controls are undersized.** Measured action buttons are generally **41 px** high, including Pause/Stop, versus the proposal’s 44 px default, 48 px touch controls and 56 px job actions. See the raw per-widget measurements; mapped widgets inside scrollers can still be outside the visible viewport.
5. **Settings remain structurally different.** Controller remains nested under Planning defaults, and Machine control still exists inside Settings. Appearance/dark-mode/density controls are absent.
6. **Job states are not visually separated as proposed.** Running, paused, exchanging tools, stopped and ended reuse the review/sidebar layout. The required prominent state hierarchy is absent even though some action labels and confirmation gates exist.

## What must happen before calling it 1:1

1. Fix clipped compact controls and meet the defined touch/job-action dimensions.
2. Implement the proposed desktop inspector and compact page compositions, including distinct Prepare and Cut state layouts.
3. Finish the component system for all control types, then align spacing, type, colors, corners, focus and disabled states.
4. Flatten Settings, separate motion, and implement the remaining project/library/status presentations.
5. Establish an explicit reference image for each otherwise text-only window/state. Use accepted user overrides when creating those references.
6. Compare matched viewport/content/state captures against that reference set. Exercise 320, 390, 600, 768, 840, 1024, 1280 and 1440 widths, short landscape, 200% text, Polish labels and keyboard behavior. This audit covers two sizes and does not certify the remaining device/accessibility matrix.

The previous 268 passing functional tests and >90% GUI line coverage do **not** prove visual fidelity. They did not catch these clipped controls or establish screenshot equivalence. No application code was changed and no new functional test run was needed for this review.
